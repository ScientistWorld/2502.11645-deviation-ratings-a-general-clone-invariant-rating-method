The main scoring repairs for the next iteration follow directly from these runs:

- Use fresh hidden games and transformations. Public tables and property targets currently reveal the entire task family used for ranking; constant ratings plus a documented dominance special case saturate it.
- Couple ratings to their declared game-theoretic meaning and remove the reward for unbounded units. Recomputing only CCE feasibility validates a separate submitted distribution. The same actual reference ratings multiplied by 10^6 receive a margin of 10^6, without better research.
- Construct action counts, dominance relations, and mixture weights from trusted benchmark definitions. Validate all actions and both players; a submitted one-action list, reversed/omitted pairs, phantom actions, or invalid mixtures currently move the comparison itself.
- Enforce all advertised constraints on the hidden path. Hidden mixture scoring omits original-rating drift, hidden offset scoring silently centers away absolute error, and the clone path does not check recommendation feasibility or rating correctness.
- Require numeric finite ratings and distributions, explicitly rejecting booleans and numeric strings. Validate nonnegative normalized probability mass using overflow-safe accumulation before any metric calculation. Reject nonfinite intermediate values before reductions: sparse NaNs currently yield entirely finite perfect scores, so checking only the final scores is insufficient.
- Run the evaluator with trusted imports and preserve results outside the writable submission tree. Restoring `eval/` leaves a root `sitecustomize.py` on `PYTHONPATH`; its exit hook rewrites the computed scores while retaining the full baseline schema. Its [test stdout](redteam/python_startup_shortcut/test.log) shows the poor U result, whereas its [persisted score file](redteam/python_startup_shortcut/scores_test.json) claims perfect errors and margin 10^12. Enforce one declared output location to prevent alternate checkpoints from overriding the actual method.

Directly prewriting scores, claiming success/timing fields, replacing the packaged baseline checkpoint, changing public payoff tables, and changing reference coefficients did not improve the actual test outputs. Nonfinite margin/all-NaN-rating outputs were accepted, but this audit does not assume that an external ranker would award them a high rank. The stronger sparse-NaN shortcuts and finite margin inflation need no such assumption.
